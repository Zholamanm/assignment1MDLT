Scaled Dot-Product Attention – Overview

Scaled dot-product attention is the core operation in the Transformer architecture. It lets every token in a sequence attend to all other tokens, forming a weighted mixture of their values based on how well their keys match their own query. The formula is:

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V
\]

Here’s what happens step‑by‑step:

1. Queries (Q), Keys (K), and Values (V) are all linear projections of the input embeddings. Each has shape [batch, heads, seq_len, d].
2. Score matrix: \(QK^\top\) computes a dot product between every query and every key, giving an \(N \times N\) matrix of raw similarity scores.
3. Scaling: Dividing by \(\sqrt{d_k}\) (the key dimension) prevents the dot products from growing too large as \(d_k\) increases. Without this, the softmax would saturate and gradients would vanish.
4. Softmax: Row‑wise softmax turns scores into a probability distribution over keys—each token decides how much to “look at” each other token.
5. Weighted sum: The output is the sum of values, weighted by those attention probabilities.

This mechanism replaces recurrence and convolutions in traditional RNNs, enabling full parallelization and dramatically improved training speed.

---

Original Paper: *Attention Is All You Need* (Vaswani et al., 2017)

The paper introduces the Transformer, a sequence‑to‑sequence model built entirely on attention, with no recurrence or convolutions. Key contributions:

- Self‑attention (intra‑attention): relates different positions of a single sequence to compute a representation.
- Multi‑head attention: projects Q, K, V into multiple subspaces in parallel, letting the model jointly attend to information from different representation angles.
- Positional encoding: injects order information (via sine/cosine functions) since attention is permutation‑invariant.
- Efficiency: The quadratic cost \(O(N^2)\) in sequence length is the main bottleneck, motivating later work on sparse/linear attention.

The scaled dot‑product attention formula above is the mathematical heart of the Transformer and remains the standard building block in modern LLMs.

import torch
import torch.nn.functional as F

# Hyperparameters
batch_size = 2
seq_len = 3
d_k = 8   # key dimension
d_v = 16  # value dimension

# Random inputs (replace with real embeddings in practice)
query = torch.randn(batch_size, seq_len, d_k)
key   = torch.randn(batch_size, seq_len, d_k)
value = torch.randn(batch_size, seq_len, d_v)

# Compute attention
output, attn_weights = F.scaled_dot_product_attention(
    query, key, value
)

print("Output shape:", output.shape)       # (2, 3, 16)
print("Attention weights shape:", attn_weights.shape)  # (2, 3, 3)


What this does:

- query, key, value are the three projections of the input sequence.
- F.scaled_dot_product_attention internally performs the full scaled‑dot‑product attention (including causal masking if desired) and returns both the weighted output and the attention weights.
- The output is a weighted mixture of the value vectors, where the weights are determined by how well each key matches the query.

You can also enable causal masking (important for decoders) by passing attn_mask or using torch.nn.functional.scaled_dot_product_attention with appropriate masking logic.

Final Answer

Scaled dot‑product attention computes a weighted sum of value vectors using queries and keys. The formula is:

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V
\]

The original paper "Attention Is All You Need" (Vaswani et al., 2017) introduced the Transformer, which relies entirely on this mechanism—replacing recurrence and convolutions with pure attention for faster parallel training and better scalability.

A minimal PyTorch implementation is:

import torch
import torch.nn.functional as F

query = torch.randn(2, 3, 8)
key   = torch.randn(2, 3, 8)
value = torch.randn(2, 3, 16)

output, attn_weights = F.scaled_dot_product_attention(query, key, value)


This produces an output of shape (2, 3, 16) where each token’s representation is a weighted combination of the values, with the weights reflecting how well each key matches the query. The scaling by \(\sqrt{d_k}\) keeps the softmax well‑conditioned and prevents gradient vanishing. (2/2)
